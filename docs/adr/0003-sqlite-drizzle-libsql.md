# 0003. SQLite through Drizzle and libSQL to start

- Status: Accepted
- Date: 2026-11-17

## Context

Spec 11: free to run, self-hostable. The user asked for SQLite to start, with
an ORM.

## Decision

Drizzle ORM on `@libsql/client`: a local SQLite file in development and on a
Docker volume, `:memory:` in tests, and a libSQL server (e.g. Turso) later
without code changes. Migrations are generated by drizzle-kit, committed, and
applied at API boot. Repositories avoid SQLite-only SQL so a move to Postgres
stays a driver change.

## Consequences

Zero database infrastructure; fast real-database tests. One writer process:
the API runs as a single replica until the store changes.

## Alternatives considered

better-sqlite3 (native build step; no remote mode); Prisma (heavier runtime,
weaker SQL control); Postgres now (an extra service before it is needed).
